## 本地预览

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8000>。页面使用 ES 模块，需要通过 HTTP 预览。

## 文件结构

- `index.html` / `style.css`：首页与共享样式，包含移动端布局、键盘焦点和减少动态效果支持。
- `blog.js`：文章加载、倒序排列、归档与文章锚点。
- `render.js`：首页及编辑器共用的安全正文、图片渲染。
- `posts.js`：数据校验、日期兼容、UTF-8 编解码和发布去重。
- `github.js`：GitHub 身份验证、读取与带 SHA 的原子提交。
- `editor.html` / `editor.js`：作者验证、自动保存草稿、预览、发布与单篇删除。
- `posts.json`：文章数据；支持旧的 `YYYY-MM-DD` 及新的 `YYYY-MM-DDTHH:mm` 日期。

## 部署与作者发布

1. 将本站文件部署到 `albertyizhan/tgyizhan.github.io` 的 `main` 分支，在 Settings → Pages 选择 Deploy from a branch、main、根目录。
2. 在首页底部进入「作者入口」。创建 GitHub fine-grained personal access token，仅选择该仓库，授予 Contents: Read and write 并设置有效期。
3. 输入令牌验证身份，编辑标题、正文，确认预览后发布。文字和图片链接一次提交到 `posts.json`，等待 Pages 部署完成。
4. 已发布列表支持打开原文和逐篇确认删除。新文章发布后立即出现在作者页列表中。

更换仓库、账户或发布分支时，修改 `posts.js` 顶部配置。GitHub 在服务端校验令牌权限；作者页同时检查账户为 `albertyizhan`。

凭证保存在当前标签页的 `sessionStorage`，不写入文章或永久本地存储。刷新可复用，点击「退出」清除。浏览器的会话恢复可能恢复标签页及其会话数据，使用完毕建议主动退出。

## 写作与草稿

草稿自动保存在此浏览器、此站点的 `localStorage`，刷新或重新打开作者页可恢复。每个浏览器站点保留一篇草稿，不支持多标签页同时编辑或跨设备同步。发布成功或确认「开始新稿」后清空草稿。浏览器禁止存储时，页面显示未保存状态并在离开时提醒。

正文按纯文本展示，不执行 HTML，也不解析其他 Markdown 格式。HTTPS 图片直链独占一行时会自动显示，也支持：

```text
今天去散步了。

![傍晚的天空](https://example.com/sunset.jpg)

想把这一刻留下来。
```

支持带查询参数、无扩展名的图片直链。图片直接从图床加载，点击可查看原图；加载失败显示原图链接。图床需支持公开 HTTPS 直链和外链展示。

标题最多 100 字符，正文最多 20,000 字符；文章库以 UTF-8 计总上限为 700 KB，图片文件不计入。达到上限后需要拆分存储。首次部署必须包含 `posts.json`，没有文章时内容为 `[]`。目前不支持修改已发布文章。

## 发布一致性

提交使用读取时的文件 SHA 防止并发覆盖。发布或删除遇到网络中断时可重试：已存在的相同文章不会再次提交，已删除的文章不会再次删除。若同一草稿 ID 已发布但正文不同，会保留当前草稿并要求核对；不会静默覆盖或自动创建重复文章。
